# 体育课一体机方案（选型 · 采购 · 部署）

> 目标：一台**带屏、能推到场地、开机就能上课**的设备。
> 技术前提见 [../README.md](../README.md) 的「运行环境要求」；
> 给体育组的 BYOD 版本见 [设备清单.md](设备清单.md)。

---

## 一、先定约束：这台机器必须满足什么

这台设备不是「随便一台能开网页的电脑」。从项目的判定逻辑倒推，得到 6 条约束（按重要性排序）：

| # | 约束 | 为什么 | 不满足会怎样 |
|---|---|---|---|
| 1 | **GPU 必须能走 WebGL2 硬件加速** | 单帧推理 GPU 19ms vs CPU 30–60ms；项目自设上限 30fps | 掉到 15fps 以下，反馈延迟到没法上课 |
| 2 | **摄像头必须能离开屏幕** | 仰卧起坐 / 靠墙静蹲**必须侧面低角度**拍；俯卧撑斜侧 45° 即可，但正面仍不稳 | 这两个动作直接废掉，俯卧撑降级 |
| 3 | **必须有外放音箱** | v1 有「语音播报」+「语音指导」两路语音反馈 | 老师得一直盯着屏幕，等于少了一路反馈 |
| 4 | 能跑本地 HTTP 服务 | WASM 走 fetch 会被 `file://` 的 CORS 拦死；摄像头要安全上下文 | 页面白屏 |
| 5 | 浏览器 ≥ Chrome / Edge 91 | 需要 WASM SIMD | 页面白屏 |
| 6 | **开机即用，老师不碰命令行** | 上课场景 | 老师不敢用，设备吃灰 |

### ⚠ 第 2 条是最容易做错的一条

「带屏一体机」的直觉做法是把摄像头装在屏幕顶上。**但这一装，三个动作全废** ——
仰卧起坐、靠墙静蹲的机位要求都是「侧面、镜头压低到地面附近」；俯卧撑虽然 2026-10-28 已放宽
到「斜侧 45°、地上或矮凳都行，不必与身体同高」，但**机位仍然不在屏幕那一侧**才是它最好用的状态。

而且摄像头和屏幕的**位置本身就是矛盾的**：

- 摄像头要在**侧面低处**（拍动作侧面轮廓）
- 屏幕要**正面朝向师生**（上课要看读数）

所以结论是：**屏幕和摄像头必须分离。** 屏幕是一体机的一部分，摄像头是一支独立的 USB 摄像头。

> 这一条决定了采购清单里必须有 **有源 USB 延长线** 和 **小三脚架**。
> 它们不是"配件"，是**必需件** —— 少了它们，这台机器只能上 4 个正面动作。

## 二、候选整机对比

四个整机候选，外加一个形态完全不同的平板（见 ⑤）。
整机之间的判据是 **GPU 算力相对项目最低档（Intel UHD 630 = 422 GFLOPS）的比例**，
这是唯一的硬门槛，其余都是次要项。

| 方案 | CPU | iGPU | 相对最低档 | 价格 | 判定 |
|---|---|---|---|---|---|
| **i5-8500T 迷你主机（二手）** | 6 核 35W | UHD 630 = 422 GFLOPS | **100%** | ¥600–1000 | ✅ **推荐** |
| **N305 迷你主机（全新）** | 8 核 15W | 32EU @1.25G = 640 GFLOPS | **152%** | ¥1300–1800 | ✅ 有富余 |
| N100 迷你主机（全新） | 4 核 6W | 24EU @750M = 288 GFLOPS | **68%** | ¥800–1200 | ⚠️ 低于底线，先测 |
| RK3588 板卡 + Android | 4×A76+4×A55 | Mali-G610 = 450 GFLOPS | 107% | ¥900–1400 | ⚠️ 软件栈要填坑 |
| **安卓平板（旗舰 SoC）** | 8 核 | Adreno 7xx / Mali-G7xx ≈ 1–2.5 TFLOPS（理论） | 250–600%（理论） | ¥2000–4000 | ⚠️ 先过三关，见 ⑤ |

### 逐条说明

**① 二手 i5-8500T / i5-9500T 迷你主机 —— 首选**

- 机型：Dell OptiPlex 3070 Micro / HP ProDesk 400 G5 Mini / 联想 M720q（1L 小机箱）
- **iGPU 与项目「最低档」基线是同款 UHD 630**，算力 100% 达标，零猜测
- 6 核落进项目「建议档」的下沿，同时满足多核要求（N100 的多核只有最低档的 92%）
- 二手便宜、配件通用、坏了换一台成本极低
- 代价：不是全新，无保修。作为**批量采购**要多买一台作备件

**② N305 迷你主机 —— 想全新 + 要余量就选它**

- 8 核 + 32EU 核显（640 GFLOPS，是 N100 的 2.2 倍），比最低档高 52%
- 为 **v3 多人同屏**留了余量（多人场景要把模型切到 `lite` 并跑多实例，吃 GPU）
- 全新有保修，15W 低功耗 + 静音，适合固定在教室/体育馆
- 代价：价格是二手 i5-8500T 的 1.5–2 倍

**③ N100 —— 便宜，但有一个数字没过线**

N100 的 CPU 其实不差（单核 ≈ i3-8100，甚至略好），**问题在核显**：

| | i3-8100 | N100 | 比值 |
|---|---|---|---|
| CPU 单核（Geekbench 5） | ~970 | ~990 | **102%** ✅ |
| CPU 多核 | ~3100 | ~2840 | 92% ⚠️ |
| iGPU FP32 | 422 GFLOPS | 288 GFLOPS | **68%** ❌ |

从 Gen9 到 Gen12 的每-FLOP 效率是提升的，所以 68% 不必然等于"慢 32%"。
但这是**唯一一个低于项目自订底线的候选**，不能拿采购决策去赌。
**如果要考虑它，先买一台实测**（验收方法见第六节），不行再换二手 i5。

**④ RK3588 —— 硬件够，软件栈是拦路虎**

Mali-G610 的 450 GFLOPS 其实比 UHD 630 还高一点，但 RK3588 在 Linux 上的
Chromium WebGL 加速是出了名的难搞：

- Snap 版 Chromium **永远回退 SwiftShader**（纯软件渲染），GPU 加速直接失效
- 要 Debian 版 + **Wayland** + Panfrost 才可能开起来
- Chromium 113 + Mali 驱动有 WebGL **内存泄漏**；升到 130 又**驱动识别失败**
- 瑞芯微官方论坛版主的原话：「webgl 建议用 android 的 chrome 进行测试，
  linux 版本的 chrome 并没有对 arm 芯片组进行优化」

**如果一定要用（比如要复用手上的板子）**：走 **Android + Chrome**，
它是官方推荐路线，且 Android 把 `http://localhost` 视为安全上下文，
本机起服务再开 Chrome 正好绕开项目「局域网 IP 不是安全上下文」的限制。
外接摄像头能不能被 Chrome 枚举到，同样要按 ⑤ 的第一关验 ——
这是整条 Android 路线（包括板卡）的共同前提。

**⑤ 安卓平板 —— 便携是真的，但要先过三关**

平板有一个笔记本没有的结构优势：**后置摄像头和屏幕在相反的两面**。
平板立在支架上、屏幕朝老师、镜头朝学生，4 个正面动作可以直接拍，不用外接摄像头。
但 2 个必侧面动作（仰卧起坐 / 靠墙静蹲）仍然要外接 UVC，俯卧撑也会明显受益 —— 这里就是第一关。

| 关卡 | 具体情况 | 能不能绕 |
|---|---|---|
| **外接摄像头** | Android 9 起有 `FEATURE_CAMERA_EXTERNAL`，但**是否实现由 OEM 决定**，多数消费级平板没编进去；厂商相机 App 认得 UVC ≠ Chrome 的 `getUserMedia` 枚举得到 | 只能按机型验。绕路（手机当 IP 摄像头）要付 100–300ms 延迟 + 第二台设备的运维，v1 不值得 |
| **屏幕尺寸** | 平板 11–13"，而第一节的下限是 21.5"（24" 才舒服），3–5 米外读数看不清 | ❌ 物理问题，钱和技术都解决不了 |
| **开机即用** | 安卓没有 Chrome kiosk | ✅ 但要写代码，见下 |

**性能不是主要障碍，但门槛正好卡在旗舰 SoC 上：**

| 档位 | 典型 SoC | 理论 FP32 量级 | 判定 |
|---|---|---|---|
| 白牌 / 入门 | Unisoc T616、Helio G85/G99 | ~0.1–0.3 TFLOPS | ❌ 出局 |
| 中端 | SD 680 / 6 Gen 1、天玑 700 | ~0.3–0.6 TFLOPS | ⚠️ 与 N100 同级，没过线 |
| 旗舰 | SD 870/888/8 Gen 1+、天玑 8100/9000+ | ~1–2.5 TFLOPS | ✅ 有资格进实测 |

> 理论值只作量级参考。移动 GPU 的有效吞吐受带宽、驱动、热限制影响，
> 不能按 GFLOPS 线性折算 —— 这是它和 UHD 630 最大的区别。

移动端还有三个 PC 上没有的风险：

1. **GPU 委托可能静默回退 CPU** —— 部分移动 GPU 缺 float 渲染目标 / 线性过滤扩展，
   页面照常显示，只是徽标变成 `CPU`。这正是第六节第 3 条要看的东西
2. **热节流** —— 平板无风扇，45 分钟课的后半段是另一个成绩，`perf-matrix` 要跑满 20 分钟才算数
3. **高 DPI 反噬** —— 12" 2K 屏 `devicePixelRatio` = 2，画布后台缓冲翻 4 倍；
   必须把画布锁在 640×480、CSS 放大，否则 GPU 时间会花在渲染而不是推理上

**开机即用**三条路，代价依次递增：

| 做法 | 代价 |
|---|---|
| 第三方 kiosk App（如 Fully Kiosk） | 授权费 + 开机自启 + 禁休眠 + 禁电池优化；无 GMS 的平板还得侧载 |
| MDM / device-owner | 要学校 IT 做，个人部署不现实 |
| **自建 APK 壳（推荐）** | `WebViewAssetLoader` 把页面挂在 `https://appassets.androidplatform.net/` 下 —— **顺带解决安全上下文和 CORS，不需要 Node、不需要 Termux**；`onPermissionRequest` 放行摄像头，`BOOT_COMPLETED` 自启 |

> 真要做平板方案，**正确路线是自建 APK 壳，不是 Termux + Chrome kiosk** ——
> 后者对老师是不可维护的。

**成本与便携的真实对比：**

| 方案 | 含配件重量 | 价格 | 软件工作量 | 算力确定性 |
|---|---|---|---|---|
| 二手 i5 迷你主机 + 24" 屏 | ~6kg（不含推车） | ¥1700–2900 | 0 | 100% 已知 |
| 迷你主机 + 15.6" 便携屏 + 充电宝（第七节） | ~3.5kg | ¥1500–2600 | 0 | 100% 已知 |
| 二手旗舰平板 + UVC + hub + 音箱 + 支架 | ~2kg | ¥2000–3200 | 要写 APK 壳 + 移动适配 | 待实测 |

便携的幅度是「少搬一台 1L 主机和一块屏」，不是「从推车变成口袋」——
侧面摄像头、三脚架、有源音箱、供电，两个方案都得带。
**为省 1.5kg 多花 ¥300，再背上「摄像头可能用不了 / 可能没走 GPU / 上课中途降频」的风险，不划算。**

**结论**：平板是 v2「老师个人随身、1–2 人用」的形态，不是「全班看的一体机」。
真要买，先按第六节验，其中这两条不过就不用往下走：

1. 插上 UVC，`chrome://media-internals` 里能看到第二路 `videoinput`（第 6 步的前提）
2. 计数页徽标是 `GPU` 不是 `CPU`（第 3 步）

> iPad 直接排除：Safari 拿不到外接 UVC，也没有本地服务这一层。

## 三、推荐配置与 BOM

以**首选方案（二手 i5-8500T）**为例，一件一件列清楚：

### 主机与显示

| 件 | 规格要求 | 参考价 |
|---|---|---|
| 迷你主机 | Dell 3070 Micro / HP 400 G5 Mini / 联想 M720q，**i5-8500T 或 i5-9500T**，8GB DDR4，256GB SSD | ¥600–1000 |
| 显示器 | **24" 起**（下限 21.5"），1080p，带 VESA 75/100 孔。触摸可选，见下 | ¥350–900 |

> **屏幕尺寸别省。** 体育课上师生在 3–5 米外，21.5" 是"勉强"，24–27" 才舒服。
> 如果预算允许，**32" 或小电视**的观感提升远大于换更好的主机。

> **触摸屏不是必需。** 老师操作只在两个时刻（选动作、点开始），
> 一支 ¥50 的无线鼠标或翻页笔比 ¥500 的触摸层更实用、更便宜、更不容易坏。
> 触摸屏的真实价值是「学生自己来操作」，v1 用不到。

### 摄像头（关键件，别省）

| 件 | 规格要求 | 参考价 |
|---|---|---|
| USB 摄像头 | 1080p，**UVC 免驱**，传感器 1/2.7" 以上；**带 1/4 螺口**（能上三脚架） | ¥120–250 |
| USB 延长线 | **有源（主动式）** USB 3.0，3–5 米 | ¥40–80 |
| 小三脚架 | 1/4 螺口，带云台，**高度能降到 30cm 以下** | ¥40–90 |

> **延长线必须买"有源"的。** 普通无源线超过 3 米会掉帧或直接认不到设备，
> 而且这种故障表现是"偶尔卡一下"，极难排查。

> **三脚架高度不用太纠结。** 俯卧撑已不再要求与身体同高（2026-10-28 改），
> 手机放地上、搭在矮凳或书包上都能用；仰卧起坐要压到接近地面，所以能降到 20–30cm 的
> 那种仍然更省事。桌面三脚架最低 40–50cm 对俯卧撑够用了。

### 音频与形态

| 件 | 规格要求 | 参考价 |
|---|---|---|
| 有源音箱 | 2.0 小音箱，3.5mm 输入，**音量要够**（场地嘈杂） | ¥100–200 |
| 移动推车 | VESA 75/100 带轮显示器支架，高度可调，**屏幕能转向** | ¥300–600 |
| 无线鼠标 / 翻页笔 | 任意 | ¥50–120 |

> **音箱别用显示器自带的。** 体育场地本底噪声大，显示器内置喇叭在 3 米外基本听不见，
> 而语音指导的价值就在"老师不用一直看屏幕"。

> **推车要能转向。** 摄像头在侧面时，屏幕要能转到正面朝学生。

### 成本汇总（三档）

| 档位 | 组成 | 总价 |
|---|---|---|
| 极简档 | 二手 i5-8500T + 21.5" 非触摸屏 + 摄像头 + 无源线 + 桌面三脚架 + 音箱（固定教室，不推车） | ¥1200–1800 |
| **推荐档** | 二手 i5-8500T + 24" 屏 + 摄像头 + **有源延长线** + 三脚架 + 音箱 + **推车** | **¥1700–2900** |
| 舒适档 | N305 + 24" 触摸屏 + 好摄像头 + 全套配件 + 推车 | ¥2400–4000 |

**对比参照**：一台能跑 MediaPipe 的新笔记本（i5-1240P 级）约 ¥3000–4000，
但内置摄像头拍不了侧面动作 —— 等于还要再加摄像头的钱。

## 四、形态怎么搭：一件一体机的物理布局

```
        [音箱]                          [侧面低角度的 USB 摄像头]
          │                                        │
          │                                  有源延长线 3–5m
          │                                        │
    ┌─────┴──────────┐                             │
    │   24" 显示器    │                             │
    │  （可转向学生）  │                             │
    └─────┬──────────┘                             │
          │ VESA                                    │
    ┌─────┴──────────┐                             │
    │  带轮推车 · 高度可调                          │
    │  [迷你主机]  [无线鼠标]                       │
    └────────────────┘
              一根电源线
```

三条摆放规则：

1. **摄像头在侧面，屏幕在正面** —— 这是分离式设计的全部意义
2. **主机挂显示器背面（VESA）** —— 少一根线、少一个"被踢到"的盒
3. **推车高度可调** —— 深蹲齐腰；仰卧起坐要压到接近地面；俯卧撑地上/矮凳就行，不必齐地

## 五、软件部署：开机就能上课

目标：**老师只按一个电源键**，剩下的自动完成。

### 5.1 服务自启

项目根目录的 `启动.bat` 已会自动探测 Node / Python 并起服务（默认 `http://127.0.0.1:4322/`）。
把它放进 Windows 开机启动：

```bat
:: 把 启动.bat 的快捷方式放进「启动」文件夹
:: Win+R 输入 shell:startup，粘贴快捷方式即可
```

或用「任务计划程序」建一条「登录时」触发的任务，指向 `启动.bat`（更可靠，可设延迟 10 秒）。

### 5.2 浏览器 kiosk 全屏

服务起来后要让它以**无地址栏全屏**方式打开计数页。用命令行参数：

```bat
:: 服务端不再自己开浏览器
node tools\serve.js --port 4322 --no-open

:: 等 2 秒让服务起来，再用 kiosk 模式打开指定页面
timeout /t 2 /nobreak >nul
start "" "C:\Program Files\Google\Chrome\Application\chrome.exe" ^
  --kiosk ^
  --app="http://127.0.0.1:4322/v1-counter.html" ^
  --no-first-run ^
  --disable-features=Translate,GlobalMediaControls ^
  --autoplay-policy=no-user-gesture-required ^
  --user-data-dir="C:\spc-kiosk"
```

几个参数为什么必须加：

| 参数 | 作用 |
|---|---|
| `--kiosk` / `--app=` | 无地址栏、无标签页，老师退不出去（也不会误关） |
| `--user-data-dir` | **必须指定**，用独立配置目录。否则会污染老师自己的浏览器配置，且摄像头授权状态会互相影响 |
| `--autoplay-policy=no-user-gesture-required` | **语音播报需要**。默认策略要求用户先交互过才允许出声，kiosk 场景下会变成"第一次播报没声音" |
| `--no-first-run` | 跳过首次运行引导页 |

> `--user-data-dir` 那个独立的配置目录只需要**第一次**手动授权一次摄像头，
> 之后会记住（按 origin 记住 `http://127.0.0.1:4322`）。所以部署流程是：
> 装好后手动点一次"允许"，之后每次开机都是全自动。

### 5.3 关闭一切干扰

| 项 | 设置 |
|---|---|
| Windows 自动更新 | 设为「工作时间不重启」，或推迟 |
| 休眠 / 睡眠 | **关闭**（上课中途黑屏最尴尬） |
| 系统通知 | 开启「专注助手」，否则弹窗会盖在 kiosk 上 |
| 屏幕保护 | 关闭 |
| 电源计划 | 「高性能」（避免 CPU 降频影响推理） |

### 5.4 参数备份

调参存在浏览器本机存储里，**kiosk 的独立配置目录 = 独立的调参存档**。
在调试台用「备份存档」导出，换机/重装时「载入存档」读回。

## 六、收货验收（30 分钟能验完，直接照做）

**每台机器到货都要跑一遍**，尤其批量采购时 —— 这是唯一能挡住"参数对了但实际跑不动"的方法。

| # | 步骤 | 通过标准 |
|---|---|---|
| 1 | 浏览器打开 `chrome://gpu` | 显示 **`WebGL2: Hardware accelerated`**（不是 `Software only`） |
| 2 | 同页看 `GL_RENDERER` | 不是 `SwiftShader` / `llvmpipe` |
| 3 | 双击 `启动.bat`，打开计数页 | 右上角徽标显示 **`GPU`**（不是 `CPU`） |
| 4 | 命令行跑 `node tools/perf-matrix.js` | 稳态 **P95 ≤ 40ms**（对应 25fps；放宽到 50ms 也能用） |
| 5 | 站进画面做 10 个深蹲 | 读数 **10**，且无多余计数 |
| 6 | 做 5 个俯卧撑（斜侧 45°、手机放地上或矮凳） | 读数 5；顺手把手机往正面转一点再拍 5 个，读数应仍然接近 5（偏差 1 次以内算正常，差得多说明机位太正） |
| 7 | 开「语音指导」做 3 次过快动作 | 音箱出声念出原因 |

第 1、2 步不过就别往下走了 —— 那是驱动/浏览器层面的问题，调参救不回来。

## 七、如果要推到操场（无市电）

体育课常在户外，这一节决定要不要买电池。

**功耗实测口径**（推理跑在 GPU 上，CPU 不会满载）：

| 组成 | 功耗 |
|---|---|
| 迷你主机（i5-8500T，推理中） | ~20–30W |
| 显示器（24" 1080p） | ~20–25W |
| 音箱 | ~5–10W |
| **合计** | **~45–65W** |

**一节体育课 45 分钟**：

| 方案 | 需要电量 | 电池 | 花费 |
|---|---|---|---|
| 普通显示器 + 迷你主机 | 45–50Wh | 户外电源 ≥150Wh（留余量） | ¥400–900 |
| **USB-C 便携显示器 + 迷你主机** | ~25Wh | **一个 100Wh PD 充电宝就够** | ¥200–300 |

> **便携显示器这条路便宜得多**：15.6" USB-C 便携屏（1080p）约 ¥400–700，
> 由 PD 供电，整机功耗降到 ~25W，一块 100Wh 的充电宝能撑 3 小时以上。
> 代价是屏幕小（15.6"）、亮度低，户外白天可能看不清。
>
> **注意**：要选**支持 PD 供电**的迷你主机。很多 N100 机型是 12V DC 圆口，
> 需要一根 PD 诱骗线（¥15–30）才能吃充电宝。

**但先说清楚**：户外白天屏幕看不清是物理问题，不是钱能解决的。
如果主要是户外课，**这块屏的价值有限** —— 建议把设备定位成
「体育馆 / 教室内使用」，户外改用手机支架 + 老师手机上的同一套页面（v2 再做移动适配）。

## 八、不要买的（反例清单）

| 别买 | 原因 |
|---|---|
| ❌ **树莓派 5** | GPU 比 RK3588 还弱（glmark2 2036 vs 4525），且共享内存没独立显存；Chromium 跑 WebGL 时容易 OOM |
| ❌ **RK3588 + Linux 桌面** | 见第二节 ④：Snap 回退软件渲染、驱动升级即失效、WebGL 内存泄漏 |
| ❌ **N100 直接批量买** | iGPU 只有最低档 68%，是唯一低于底线的候选。要买先买一台测 |
| ❌ **平板 / 手机当「全班一体机」** | 11–13" 屏不到 21.5" 下限；多数平板 Chrome 枚举不到外接 UVC；开机即用要自建 APK 壳。只适合 v2 的老师随身场景，见第二节 ⑤ |
| ❌ **内置摄像头的笔记本 / 一体机（当唯一方案）** | 摄像头在屏幕顶上 = 仰卧起坐 / 靠墙静蹲全废，俯卧撑只剩正面视角（不稳，等于半废） |
| ❌ **无源 USB 延长线 > 3m** | 掉帧或认不到设备，故障表现是"偶尔卡一下"，极难排查 |
| ❌ **显示器自带喇叭当音箱** | 场地嘈杂听不见，语音反馈等于没有 |
| ❌ **21.5" 以下的小屏** | 3–5 米外读数看不清，上课时学生要凑到屏幕前 |

## 九、一句话总结

**首推：二手 i5-8500T 迷你主机（¥600–1000）+ 24" 屏 + 一支能上三脚架的 USB 摄像头
+ 有源延长线 + 小三脚架 + 有源音箱 + 带轮推车**，整套约 **¥1700–2900**。

主机不用买最快的那档 —— 项目的瓶颈在**「有没有走 GPU」**，不在 CPU 有多强。
把预算花在**屏幕尺寸、摄像头质量、音箱音量**上，上课体验的提升比换更好的 CPU 大得多。

**平板不是同类替代品**：屏幕尺寸和侧面摄像头两关它都过不去，省下的 1.5kg 抵不了这部分风险（见第二节 ⑤）。
