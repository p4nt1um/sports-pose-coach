# 参数依据：每个可调数字「为什么是这个值」

> 面向：要改阈值的人（体育老师 / 调试台使用者 / 后来的自己）
> 对应配置：`data/exercises.json`（本表由 `node tools/test-config.mjs` 校验，
> **参数改了忘改本表会直接报红** —— 这是防止文档腐烂的唯一可靠办法）

## 怎么读这张表

- **现值** 必须与 JSON 完全一致，否则 `test-config.mjs` 报错。
- **改它会怎样** 才是重点。本表不写"这是什么"（JSON 里 `meta` 已经写了），
  只写"为什么选它"和"动了以后会付出什么代价"。
- **所有阈值都是初值**，来自标准动作 + 关键点偏差的经验估算。
  `data/exercises.json` 开头的 `note` 已经写过：**必须用 `tools/tune.html` 对真人校准**。
  本表的价值在于：校准的时候你知道往哪个方向调、会牵连什么。

## 几个跨动作的概念

| 概念 | 说明 |
|---|---|
| `smooth.minCutoff` | One Euro 滤波的截止频率（Hz）。**越低越平滑但越滞后**。慢动作（深蹲、静力）用 1.0–1.2；最快的动作（高抬腿）要 1.8，否则峰值被削平、直接漏计 |
| `smooth.beta` | 速度系数：信号变化快时自动放宽截止频率。**它决定"快速段会不会被平滑拖慢"**。快动作要 0.02–0.03，慢动作用 0.01 就够 |
| `median` | 滑动中位数窗口（帧）。用来**丢弃**单帧塌陷，而不是摊薄它。代价是 (N−1)/2 帧延迟，5 帧 @30fps ≈ 67ms |
| `minHoldFrames` | 进入新相位要连续满足几帧。30fps 下 2 帧 = 67ms。**快动作必须设 1**，否则穿越窗口太短会漏计 |
| `minRepMs` / `maxRepMs` | 时长口径是「进入末相位 → 回到起始相位」，约等于半周期。`minRepMs` 挡抖动、`maxRepMs` 抓「停住不动」 |
| `lossResetMs` | 关键点丢失多久后复位相位。太短会把"人晃出画面一下"当成新一段，太长会把两段动作接成一次 |
| `minConfidence` | 主信号可信度下限。**它不是越高越安全**：设高了会在侧拍/遮挡场景把整条信号判死，表现是"计数恒为 0 且没有任何拒绝记录"（详见 `tpc-signals.js` 里 `combine()` 的注释） |
| `guards` 的条件 | **写的是「应该成立的条件」**。不成立才打标记。所以 `gte: 150` 的意思是"应该 ≥150"，读到 145 就打「没撑直」 |
| `fsm.verb` | 不是数字，所以不进这张表逐条检查，但它是**教学语言的来源**：两个词依次对应「起始相 → 末相」和「末相 → 起始相」。动词写歪了不会报错，只会让老师看到别扭的话（「下放」写成「上去」），改 JSON 即可 |

## 深蹲 squat

| 参数 | 现值 | 为什么是这个值 / 改它会怎样 |
|---|---|---|
| squat.signals.kneeAngle.smooth.minCutoff | 1.2 | 深蹲全程 2–3 秒，属慢动作，1.2Hz 足以压住关键点抖动。调到 0.8 以下常见滞后：蹲到底时读数还在往下走，谷值被抬 → 判不到底 |
| squat.signals.kneeAngle.smooth.beta | 0.01 | 站立/蹲底都是准静止段，速度项几乎不起作用。给 0.01 只为让快速下蹲那 300ms 不被过度平滑（谷值被削 = 少数几次） |
| squat.fsm.phases.stand.enter.gte | 158 | 站直时 BlazePose 膝角读数通常 168–175（**不是 180**，关键点不在关节中心）。158 留了 10° 余量，否则"站直了却回不到起始相"，永远数不出来 |
| squat.fsm.phases.bottom.enter.lte | 100 | 大腿与地面平行时膝角理论 90°，实际读数 92–100（同一偏差）。取 100 而不是 90 是在补这个偏差，不是放宽标准 |
| squat.fsm.minRepMs | 400 | 最慢的连续深蹲上升段也在 500ms 以上，400 只用来丢抖动。调到 200 会把膝盖弹动算成一次 |
| squat.fsm.maxRepMs | 8000 | 蹲在底部歇一下再起来是课堂上常见行为，超过 8 秒判「停住不动」。调到 3000 会误杀体能差的学生 |
| squat.fsm.minHoldFrames | 2 | 30fps 下 67ms。1 帧会把单帧尖峰算进去 |
| squat.fsm.lossResetMs | 500 | 半秒看不到人足够说明"人不在画面里了"。调到 2000 会把人走出画面又回来的一段接成一次 |
| squat.fsm.minConfidence | 0.5 | 深蹲要求膝、髋、踝都可见，world 坐标下正常可见度 0.7+。低于 0.5 基本就是被遮挡 |
| squat.fsm.phaseMaxDwellMs.bottom | 1800 | 底部停留超 1.8 秒就打「是否坐着完成？」标记（**不阻断计数**）。单靠膝角分不清深蹲与坐椅子，只能把特征暴露给老师判断 |
| squat.fsm.guards.0.lte | 55 | `torsoLean` 是躯干与垂直轴夹角。深蹲最低点正常前倾 25–40°，超过 55° 属"弯腰"而非"下蹲" |
| squat.fsm.guards.1.gt | 70 | 「蹲得过深」：膝角小于 70° 时膝盖前移过大，中学生不要求。`info` 级，只记录不播报成错误 |

## 开合跳 jumping_jack

|---|---|---|
| jumping_jack.signals.ankleSpread.smooth.minCutoff | 1.6 | 开合跳 1–2 秒一轮，比深蹲快。1.6 是"压得住抖动"与"跟得上开合"的交点；1.2 会让开合峰值被削（少计） |

| jumping_jack.fsm.minRepMs | 120 | 快速开合跳半周期可到 300ms。120 只丢抖动，不再往上调（调高会漏计快节奏） |
| jumping_jack.fsm.maxRepMs | 4000 | 并腿站住 4 秒以上判「停住不动」 |
| jumping_jack.fsm.minHoldFrames | 2 | 30fps 下 67ms，足以滤掉脚落地时的单帧抖动 |
| jumping_jack.fsm.lossResetMs | 500 | 跳起时容易短暂出画，半秒容差刚好 |
| jumping_jack.fsm.minConfidence | 0.45 | 踝距要两只踝都可见。0.45 允许一只脚短暂模糊 |
| jumping_jack.fsm.guards.0.lt | 0 | `wristHeight = (腕 − 肩中点)/躯干长`，图像坐标 y 向下 → 手举过头顶时腕在肩**上方**、值为负。所以"应小于 0"，不满足即「手臂未举过头顶」 |

## 俯卧撑 pushup

| 参数 | 现值 | 为什么是这个值 / 改它会怎样 |
|---|---|---|
| pushup.signals.elbowAngle.median | 5 | 5 帧中位数吃掉单帧塌陷（俯卧撑是最容易被自身躯干遮挡的动作）。代价约 67ms 延迟，远小于一次动作 1–2 秒 |
| pushup.signals.elbowAngle.smooth.minCutoff | 1.2 | 俯卧撑 2–3 秒一次，与深蹲同档 |
| pushup.signals.elbowAngle.smooth.beta | 0.01 | 顶/底都是准静止段；只为快速下降段留一点跟随 |
| pushup.fsm.phases.up.enter.gte | 132 | **2026-10-28 从 150 放宽**。150 只剩 10° 余量：学生撑不直（顶部 145°）或读数有 10° 系统偏差就整节课 0 分。放宽后"做不全也计数"，质量另用 guards 标记 |
| pushup.fsm.phases.down.enter.lte | 116 | 同上，从 105 放宽。116° 的肘角已明显弯曲，是与"只弯手臂不下身"区分开的合理下限 |
| pushup.fsm.minRepMs | 200 | 俯卧撑半周期最短约 400ms，200 只丢抖动 |
| pushup.fsm.maxRepMs | 6000 | 在底部撑住超过 6 秒判「停住不动」。比深蹲短，因为撑住不动通常是休息而非训练 |
| pushup.fsm.minHoldFrames | 2 | 30fps 下 67ms。配合 `median: 5` 已经是双重保护 |
| pushup.fsm.lossResetMs | 600 | 趴姿下关键点更容易短暂丢失（地面遮挡、手臂重叠），比深蹲略宽松 |
| pushup.fsm.minConfidence | 0.35 | **侧拍时远侧手臂被躯干压住，可见度天生低**。设 0.45 会把整条信号判死（静默 0 计数）。配合 `side: "auto"` 后可以放心调低 |
| pushup.fsm.guards.0.gte | 150 | 「应撑直到 150°」，不满足即打「没有完全撑直（已计入，但幅度偏小）」。这是**分级**，不是计数门槛 |
| pushup.fsm.guards.1.gte | 55 | `torsoTilt` 是躯干与垂直轴夹角，趴着时 70–90。小于 55° 说明人不是趴着的（站着弯手臂） |
| pushup.fsm.guards.2.gte | -18 | `bodyLine` 是「髋偏离肩—踝连线」的角。**下侧留 18° 而上侧只留 12° 是不对称的，故意的**：关键点不在关节中心，视觉上笔直的平板读出来是 −4~−9°，不是 0。若写成 ±10° 会把正常平板判成塌腰 |
| pushup.fsm.guards.2.lte | 12 | 拱背（髋高于连线）在真实俯卧撑里少见、且幅度小，12° 足够。写大了就分不出"略拱"和"撅臀" |
| pushup.fsm.guards.3.lt | 100 | 底部肘角应小于 100°（全程俯卧撑），否则「下降幅度不足」 |

## 维护约定

1. **加一个参数 = 加一行**。`node tools/test-config.mjs` 会遍历 `exercises.json` 里所有可调数值，
   少一行就报红（关键点索引 `chain` / `point` / `refPoints` / `a` / `b`、`order`、`version` 不算可调参数）。
2. **改一个值 = 改这一行的现值**。现值与 JSON 不一致也报红 —— 这是本表唯一的"防腐"机制。
3. 加新动作时，`meta.signalTypes` / `meta.fsmFields` 写"这是什么"，本表写"为什么是这个值"，两者不重复。
