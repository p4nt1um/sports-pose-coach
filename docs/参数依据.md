# 参数依据：每个可调数字「为什么是这个值」

> 面向：要改阈值的人（体育老师 / 调试台使用者 / 后来的自己）
> 对应配置：`data/exercises.json`（本表由 `node tools/test-config.mjs` 校验，
> **参数改了忘改本表会直接报红** —— 这是防止文档腐烂的唯一可靠办法）

## 怎么读这张表

- **现值** 必须与 JSON 完全一致，否则 `test-config.mjs` 报错。
- **改它会怎样** 才是重点。本表不写"这是什么"（JSON 里 `meta` 已经写了），
  只写"为什么选它"和"动了以后会付出什么代价"。
- **所有阈值都是初值**，来自标准动作 + 关键点偏差的经验估算。
  `data/exercises.json` 开头的 `note` 已经写过：**必须用 `tools/tune.html` 对真人校准**。
  本表的价值在于：校准的时候你知道往哪个方向调、会牵连什么。

## 几个跨动作的概念

| 概念 | 说明 |
|---|---|
| `smooth.minCutoff` | One Euro 滤波的截止频率（Hz）。**越低越平滑但越滞后**。慢动作（深蹲、静力）用 1.0–1.2；最快的动作（高抬腿）要 1.8，否则峰值被削平、直接漏计 |
| `smooth.beta` | 速度系数：信号变化快时自动放宽截止频率。**它决定"快速段会不会被平滑拖慢"**。快动作要 0.02–0.03，慢动作用 0.01 就够 |
| `median` | 滑动中位数窗口（帧）。用来**丢弃**单帧塌陷，而不是摊薄它。代价是 (N−1)/2 帧延迟，5 帧 @30fps ≈ 67ms |
| `minHoldFrames` | 进入新相位要连续满足几帧。30fps 下 2 帧 = 67ms。**快动作必须设 1**，否则穿越窗口太短会漏计 |
| `minRepMs` / `maxRepMs` | 时长口径是「进入末相位 → 回到起始相位」，约等于半周期。`minRepMs` 挡抖动、`maxRepMs` 抓「停住不动」 |
| `lossResetMs` | 关键点丢失多久后复位相位。太短会把"人晃出画面一下"当成新一段，太长会把两段动作接成一次 |
| `minConfidence` | 主信号可信度下限。**它不是越高越安全**：设高了会在侧拍/遮挡场景把整条信号判死，表现是"计数恒为 0 且没有任何拒绝记录"（详见 `tpc-signals.js` 里 `combine()` 的注释） |
| `guards` 的条件 | **写的是「应该成立的条件」**。不成立才打标记。所以 `gte: 150` 的意思是"应该 ≥150"，读到 145 就打「没撑直」 |
| `fsm.verb` | 不是数字，所以不进这张表逐条检查，但它是**教学语言的来源**：两个词依次对应「起始相 → 末相」和「末相 → 起始相」。动词写歪了不会报错，只会让老师看到别扭的话（「下放」写成「上去」），改 JSON 即可 |
| `fsm.loose` | 儿童/体能弱的学生用的**宽松计数**阈值。规则只有一条：**只放宽末相（动作幅度那一端），起始相阈值一律不动**。放宽起点会让走动、晃动、身体后仰都更容易凑成一次，那是误计而不是宽容 |
| `fsm.qualify` | 「做到位了吗」的标准，与「算不算一次」是**两件事**。宽松模式下 `loose` 决定计数、`qualify` 决定合格，两者必须取不同值——一相等就退化成严格模式。它比对的是本次动作的 `signalMin` / `signalMax`，不是瞬时值 |

## 深蹲 squat

| 参数 | 现值 | 为什么是这个值 / 改它会怎样 |
|---|---|---|
| squat.signals.kneeAngle.smooth.minCutoff | 1.2 | 深蹲全程 2–3 秒，属慢动作，1.2Hz 足以压住关键点抖动。调到 0.8 以下常见滞后：蹲到底时读数还在往下走，谷值被抬 → 判不到底 |
| squat.signals.kneeAngle.smooth.beta | 0.01 | 站立/蹲底都是准静止段，速度项几乎不起作用。给 0.01 只为让快速下蹲那 300ms 不被过度平滑（谷值被削 = 少数几次） |
| squat.fsm.phases.stand.enter.gte | 158 | 站直时 BlazePose 膝角读数通常 168–175（**不是 180**，关键点不在关节中心）。158 留了 10° 余量，否则"站直了却回不到起始相"，永远数不出来 |
| squat.fsm.phases.bottom.enter.lte | 100 | 大腿与地面平行时膝角理论 90°，实际读数 92–100（同一偏差）。取 100 而不是 90 是在补这个偏差，不是放宽标准 |
| squat.fsm.loose.phases.bottom.enter.lte | 136 | 宽松模式只放宽**末相**：只蹲到 132° 的半蹲也算一次（132 ≤ 136）。起始相 158 不动 —— 放宽起点会让走动、晃动更容易凑成一次，那是误计不是宽容 |
| squat.fsm.qualify.signalMin.lte | 100 | 合格标准仍取「蹲到大腿平行」。宽松模式下 `signalMin` 记的是实际最小值，蹲到 132° 的那次 → 不合格。**故意与上一行不同值**：这两个数一相等，宽松模式就退化成严格模式 |
| squat.fsm.minRepMs | 400 | 最慢的连续深蹲上升段也在 500ms 以上，400 只用来丢抖动。调到 200 会把膝盖弹动算成一次 |
| squat.fsm.maxRepMs | 8000 | 蹲在底部歇一下再起来是课堂上常见行为，超过 8 秒判「停住不动」。调到 3000 会误杀体能差的学生 |
| squat.fsm.minHoldFrames | 2 | 30fps 下 67ms。1 帧会把单帧尖峰算进去 |
| squat.fsm.lossResetMs | 500 | 半秒看不到人足够说明"人不在画面里了"。调到 2000 会把人走出画面又回来的一段接成一次 |
| squat.fsm.minConfidence | 0.5 | 深蹲要求膝、髋、踝都可见，world 坐标下正常可见度 0.7+。低于 0.5 基本就是被遮挡 |
| squat.fsm.phaseMaxDwellMs.bottom | 1800 | 底部停留超 1.8 秒就打「是否坐着完成？」标记（**不阻断计数**）。单靠膝角分不清深蹲与坐椅子，只能把特征暴露给老师判断 |
| squat.fsm.guards.0.lte | 55 | `torsoLean` 是躯干与垂直轴夹角。深蹲最低点正常前倾 25–40°，超过 55° 属"弯腰"而非"下蹲" |
| squat.fsm.guards.1.gt | 70 | 「蹲得过深」：膝角小于 70° 时膝盖前移过大，中学生不要求。`info` 级，只记录不播报成错误 |


**校准（自校准 profile）** —— 把上表的绝对值翻译成「在本人满程上的位置」：

| 参数 | 现值 | 为什么是这个值 / 改它会怎样 |
|---|---|---|
| squat.calibration.reps | 3 | 校准要做几次。3 次足够让「最深那次」出现，又不会让学生先累；只做 1 次会把偶然没蹲到底的那次当成满程 |
| squat.calibration.minRange | 25 | 满程低于这个值直接判校准失败。**这是唯一能拦住「学生只抖了两下」的闸门** —— 起落计数拦不住，因为抖动本身就把「满程」撑大了 |
| squat.calibration.refRange.min | 70 | 标准成人的最深膝角估计（大腿与地面平行再往下一点）。它不参与判定，只用来把上表的绝对阈值反推成位置比例 t=(阈值−min)/(max−min) |
| squat.calibration.refRange.max | 175 | 标准成人站直时的膝角读数 168–175，取 175 作上限。**改它会平移所有阈值**：同一个绝对值在新参照下对应不同的 t |

**相似度（`similarity` 段）** —— 和「这个学生自己」比，用于看趋势。

> 先说清一件事：**`primary` 不能同时出现在 `signals` 里**。
> 每一箱是按主信号的取值切出来的，所以同一箱里主信号的值在两次动作之间必然几乎相同
> —— 把它当特征加进来，那一维的差异恒为 0，等于给一个空维度分配权重，会悄悄稀释
> 真正有信息的信号。`test-config.mjs` 会拦住这种配置。

| 参数 | 现值 | 为什么是这个值 / 改它会怎样 |
|---|---|---|
| squat.similarity.bins | 8 | 每段分几箱（两段合计 16 个进度点）。箱越少越抗噪但看不出细节，箱越多越容易被关键点抖动带偏。8 是"能看出躯干角度在动作过程中怎么变"的最小值；调到 4 以下退化成"只看几个大阶段"，调到 16 以上开始拟合噪声 |
| squat.similarity.minReps | 3 | 建立基线至少要做几次。少于 3 次估不出他自己的自然波动（`p50` / `p90`），锚点就没有意义。调到 2 会让"一次偶然做歪"直接决定他的正常水平 |
| squat.similarity.signals.0.weight | 1 | `torsoLean` 的权重。深蹲的姿势故事基本就是"躯干在一个动作里怎么倾"，所以它是唯一特征、权重 1。想加"左右膝不平衡"需要一条新的派生信号（当前没有），不是调权重能解决的 |

**两个非数值项（它们不是可调阈值，所以不占表格行）**

- `primary = kneeAngle`（进度轴）：按它等分进度箱，而不是按时间。
  所以学生蹲到底歇 3 秒也不影响形状 —— `test-similarity.mjs` 里「同一形状 + 停 2 秒」
  的差异是 0.01，而「躯干前倾 22°→40°」是 5.65。**改它等于换一把尺，旧基线全部失效。**
- `turn = min`：动作中途经过的是极小还是极大（深蹲/俯卧撑都是 `min`，
  膝角/肘角越做越小）。填错的后果是把一段动作当成两段拼起来，相似度完全失效**且不报错**。

> 分数定标：100 = 完全复制模板（实践上不可达）；**60 = 和他平时一样**；0 = 他历来最差那一档。
> "和平时一样"定在 60 而不是 0 或 100 是刻意的 —— 定在 0 会让一次毫无变化的动作看起来像退步。
> 代价：**跨学生不可比**（每个人的 60 分不是同一件事），界面与文档都必须写明这一点。

> 这两个数只影响「换算基准」，不直接判定动作。满程等于参考满程时换算结果与原值完全相同（`test-profile.mjs` 把这条钉死），所以校准不会偷偷改动上面那些调了半天的参数。

| pushup.similarity.bins | 8 | 每段分几箱（两段合计 16 个进度点）。箱越少越抗噪但看不出细节，箱越多越容易被关键点抖动带偏。8 是"能看出躯干角度在动作过程中怎么变"的最小值；调到 4 以下退化成"只看几个大阶段"，调到 16 以上开始拟合噪声 |
| pushup.similarity.minReps | 3 | 建立基线至少要做几次。少于 3 次估不出他自己的自然波动（`p50` / `p90`），锚点就没有意义。调到 2 会让"一次偶然做歪"直接决定他的正常水平 |
| pushup.similarity.signals.0.weight | 1 | `torsoTilt` 的权重。躯干角度是俯卧撑最主要的形态特征，权重最高 |
| pushup.similarity.signals.1.weight | 0.8 | `bodyLine`（身体偏移直线的角度）权重略低：它本身噪声比躯干角大，给到 1 会让评分被关键点抖动主导 |

**两个非数值项（它们不是可调阈值，所以不占表格行）**

- `primary = elbowAngle`（进度轴）：按它等分进度箱，而不是按时间。
  所以学生蹲到底歇 3 秒也不影响形状 —— `test-similarity.mjs` 里「同一形状 + 停 2 秒」
  的差异是 0.01，而「躯干前倾 22°→40°」是 5.65。**改它等于换一把尺，旧基线全部失效。**
- `turn = min`：动作中途经过的是极小还是极大（深蹲/俯卧撑都是 `min`，
  膝角/肘角越做越小）。填错的后果是把一段动作当成两段拼起来，相似度完全失效**且不报错**。

> 分数定标：100 = 完全复制模板（实践上不可达）；**60 = 和他平时一样**；0 = 他历来最差那一档。
> "和平时一样"定在 60 而不是 0 或 100 是刻意的 —— 定在 0 会让一次毫无变化的动作看起来像退步。
> 代价：**跨学生不可比**（每个人的 60 分不是同一件事），界面与文档都必须写明这一点。

> 这两个数只影响「换算基准」，不直接判定动作。满程等于参考满程时换算结果与原值完全相同（`test-profile.mjs` 把这条钉死），所以校准不会偷偷改动上面那些调了半天的参数。 注意这两条 guard 本身**不随校准缩放**（它们表达的是姿势要求），所以学生的满程小于 150 时那条提示会一直亮 —— 这是已知问题，见 §维护约定。

## 维护约定

1. **加一个参数 = 加一行**。`node tools/test-config.mjs` 会遍历 `exercises.json` 里所有可调数值，
   少一行就报红（关键点索引 `chain` / `point` / `refPoints` / `a` / `b`、`order`、`version` 不算可调参数）。
2. **改一个值 = 改这一行的现值**。现值与 JSON 不一致也报红 —— 这是本表唯一的"防腐"机制。
3. 加新动作时，`meta.signalTypes` / `meta.fsmFields` 写"这是什么"，本表写"为什么是这个值"，两者不重复。
4. **校准（`calibration` 段）不影响本表上半部分的绝对值**。`refRange` 只决定换算基准，
   满程等于参考满程时换算结果与原值完全相同（`test-profile.mjs` 验恒等性）。
   所以**该改的仍然是绝对值那一行**，不要为了适配某个学生去改 `refRange`。

## 已知问题：幅度类 guards 不随校准缩放

俯卧撑有两条 guard 表达的是**幅度**而不是姿势：

| guard | 语义 | 本该的行为 |
|---|---|---|
| `pushup.fsm.guards.0.gte` = 150 | 「没完全撑直」 | 应按学生满程折算 |
| `pushup.fsm.guards.1.lt` = 100 | 「下降幅度不足」 | 应按学生满程折算 |

它们现在**不缩放**（校准只重写 phases / loose / qualify）。后果：一个满程到不了
150° 的学生，那条「没完全撑直」会一直亮着 —— 提示是对的（他确实没撑直），
但对他的身材来说不可达。

**为什么不顺手改**：这两条 guard 与 `fsm.qualify` 表达的是同一件事（"做到位了没有"），
现在有两套数值在说同一句话（guard 150/100，qualify 116）。要让幅度类 guard 跟随校准，
必须先把"标记"与"合格"合并成一套口径 —— 否则改一处会让两个数同时变动，
出问题时查不清是谁的锅。这是独立工作项，不在校准里顺手做。
